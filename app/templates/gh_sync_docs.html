Auto-sync any repo to the CDN GitHub Actions

Add one workflow file to a repo. On every push, its contents land in the CDN under /<your-github-username>/<repo-name>/ — no PAT, no shared secret, and it's physically impossible for your workflow to write into anyone else's folder.

How it stays safe

Instead of a token you paste in, your repo asks GitHub itself for a short-lived OIDC identity token for the run. That token's "who and where" fields (repository_owner, repository) are stamped by GitHub's own servers from the real run context — a workflow file can't edit itself to lie about which repo it's running in. The CDN backend verifies that token's signature, reads the owner/repo straight from it, and uses only that to decide where your files go. Nothing in your request body or headers is trusted for the destination path.

The same token also says who you are, by GitHub's permanent numeric account ID — renaming your account, or someone registering a username you dropped, doesn't change that identity. That's what the approval step below is based on.

1. Add the workflow

Create .github/workflows/cdn-sync.yml in the repo you want mirrored. The token is short-lived and scoped to your repo already, but core.setSecret() tells GitHub to mask it from the run's logs, and passing it through env: instead of straight into the shell command keeps it out of the process list too — worth keeping both even though the token itself is harmless if it leaks (it expires in minutes and only proves who you are, it can't push files on its own).

{% raw %}name: Sync to CDN

on:
  push:
    branches: [ main ]
  workflow_dispatch:

permissions:
  id-token: write   # required — this is what lets us prove who you are
  contents: read

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7

      - name: Request GitHub OIDC token
        id: oidc
        uses: actions/github-script@v7
        with:
          script: |
            const token = await core.getIDToken('cdn.amit.is-a.dev')
            core.setSecret(token)
            core.setOutput('token', token)

      - name: Package repo contents
        run: tar --exclude='.git' -czf /tmp/payload.tar.gz .

      - name: Push to CDN
        env:
          OIDC_TOKEN: ${{ steps.oidc.outputs.token }}
        run: |
          curl -sS --fail-with-body -X POST https://cdn.amit.is-a.dev/api/gh-sync \
            -F "token=$OIDC_TOKEN" \
            -F "archive=@/tmp/payload.tar.gz"
{% endraw %}

2. Push

That's it — no repo secrets to create. On the next push, your files land at:

https://cdn.amit.is-a.dev/<your-username>/<repo-name>/

Need a raw link to one specific file instead of the folder listing? Append its path to the raw domain: https://raw.cdn.amit.is-a.dev/<your-username>/<repo-name>/<file>.

Notes

  • First sync is free, later ones need approval. The first sync from a new GitHub account goes through immediately. After that, further syncs from that account are refused until the CDN owner approves it, so after your first push, ask for approval. Approved accounts sync freely from then on. Accounts that upload abusive content are banned.
  • No videos. Any file type is accepted except video, which is detected by file extension and by file contents (renaming won't help). If the repo contains one, the whole sync is rejected and nothing is uploaded. Leave videos out of the archive, for example by adding --exclude='*.mp4' to the tar command.
  • There's no limit on file count, but the compressed archive is rate-limited: 50 MB per minute and 300 MB per hour per repo, so an archive over 50 MB is refused. Keep it small by excluding build output, for example --exclude='node_modules' in the tar command. How rate limits work.
  • Each sync fully replaces the contents of your own username/repo folder only (delete-then-upload), so removed files disappear from the CDN too. No other folder is ever touched. The storage keeps no version history, so a removed or overwritten file can't be brought back — keep the original in your repo.
  • Change branches: [ main ] to whichever branch you want mirrored.
  • Want it on every branch/tag push instead? Adjust the on: block — the destination folder is still locked to your username/repo either way.

If a sync is refused

The step now shows the server's reason in the Actions log (that's what --fail-with-body is for).

  • 403 "First sync from '<you>' was accepted; further syncs need approval…" — your account has already synced once and is waiting to be approved. Nothing is wrong with your workflow; ask the CDN owner to approve the account, then re-run the job.
  • 403 "…banned…" — the account (or the network the job ran from) has been blocked.
  • 415 "Video files are not allowed…" — the message names the file; remove it from the repo or exclude it from the archive.
  • 401 — the identity token was missing, expired or not for this service. Check that permissions: id-token: write is set and that the audience is cdn.amit.is-a.dev.
  • 429 — the archive is over the rate limit (50 MB per minute, 300 MB per hour). An archive larger than 50 MB can never pass, so shrink it, or wait if you've just synced. See rate limits.

The full request/response details are in the documentation.
